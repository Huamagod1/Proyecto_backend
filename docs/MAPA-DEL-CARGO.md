# Mapa del cargo

Qué pide el cargo de Back-end Developer de datos industriales, dónde lo construye este proyecto y cuánto lo dominas. Una fila por área: sirve para elegir qué estudiar y para saltar al lugar exacto del repositorio. Las sesiones se piden con `estudia <área>`, y su protocolo está en `AGENTS.md`, sección "Sesiones de estudio".

**Cómo leer las columnas**
- **Fases:** antes del punto, las de la Parte 1, ya construidas; después, las de la Parte 2, por construir.
- **Diagramas:** "GUIA 5.2" es la sección 5.2 de `docs/GUIA.md`; "atlas 8", la sección 8 de `docs/ATLAS-VISUAL.md`; "COMO-ABORDAR 1", la sección 1 de `docs/COMO-ABORDAR.md`.
- **Cómo verla funcionando:** comandos de Git Bash, probados el 2026-11-24 con los perfiles `completo` y `nodered` arriba. Si dice "Desde la Fase N", el área todavía no está construida.
- **Nivel:** 1, la reconozco; 2, la explico con un ejemplo del proyecto; 3, la opero y la diagnostico sin ayuda.
- **Última sesión:** la fecha del último `estudia` del área. El nivel y la fecha se anotan cuando confirmas el nivel que propone el agente.

**Antes de los comandos.** Los que usan `$MQTT_CLAVE`, `$GATEWAY_MQTT_CLAVE` o `$TOKEN` necesitan tu `.env` cargado en la terminal: `set -a; source .env; set +a`. Así las claves quedan en variables y no se imprimen. El `$TOKEN` se saca como en `docs/COMO-ABORDAR.md`, sección 3.2, técnica 1, paso 0, con el usuario `admin` y `$CLAVE_ADMIN`. En los comandos de MySQL, `$DB_CLAVE` se expande dentro del contenedor.
