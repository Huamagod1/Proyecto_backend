# CAN y J1939: la teoría mínima

> Para estudiar: reescribe esta página con tus palabras (el plan lo pide así).

## CAN
- Un bus de dos hilos donde cualquier nodo transmite cuando quiere; no hay maestro que pregunte.
- Cada trama lleva un **identificador** y hasta 8 bytes de datos. Si dos nodos hablan a la vez, gana el identificador más bajo (más prioritario) sin perder la trama: arbitraje.
- J1939 usa el identificador **extendido de 29 bits**.

## El identificador de 29 bits

| Bits | Campo | Ejemplo `0x0CF00400` |
|---|---|---|
| 3 | prioridad | 3 |
| 1 + 1 | reservado (EDP) y página de datos (DP) | 0, 0 |
| 8 | PF (PDU format) | 0xF0 = 240 |
| 8 | PS (PDU specific) | 0x04 |
| 8 | dirección de origen (SA) | 0x00 = motor 1 |

- **PF ≥ 240 (PDU2):** el mensaje es para todos y el PGN incluye a PS. `0xF004` = 61444 = EEC1.
- **PF < 240 (PDU1):** PS es la dirección de destino y no forma parte del PGN. `0x18EAFF00` → PGN 0xEA00 = 59904, destino 255 (todos).

## PGN y SPN
- **PGN** (Parameter Group Number): qué mensaje es. EEC1 = 61444, ET1 = 65262.
- **SPN** (Suspect Parameter Number): qué variable va dentro, en qué bytes y con qué escala.

| SPN | Variable | PGN | Bytes | Escala |
|---|---|---|---|---|
| 190 | velocidad del motor | EEC1 | 4 y 5 (índices 3 y 4) | 0,125 rpm/bit |
| 110 | temperatura del refrigerante | ET1 | 1 (índice 0) | 1 °C/bit, desplazamiento −40 |

- Los datos van en **little-endian**: el byte bajo primero. `E0 2E` → `0x2EE0` = 12 000 × 0,125 = **1500 rpm**.
- `0xFF` (1 byte) o `0xFFxx` (2 bytes) = **no disponible**; `0xFE`/`0xFExx` = **error**. No se inventa un valor: se omite.

## El log de ejemplo (`practica/candump-ejemplo.log`)
Formato `candump -L`: `(segundos.microsegundos) interfaz ID#DATOS`. Trae 5 segundos de MTR-03: EEC1 (1500, 1504, 1496, 1502 rpm y uno no disponible), ET1 (85, 85, 86, 86, 87 °C) y un CCVS (PGN 65265) que se ignora.

## En terreno
Un gateway con interfaz CAN; en Linux se maneja con **SocketCAN** (`ip link set can0 up type can bitrate 250000`; J1939 usa 250 o 500 kbit/s). `candump` graba y `canplayer` reproduce. Para practicar sin hardware: `sudo modprobe vcan` y una interfaz `vcan0`.
